# Python с нуля для биолога: установка и первые шаги 🐍

{{< kratko >}}
**Python** — язык программирования, который читается почти как английский текст. Для биолога он стал рабочим языком потому, что на нём написано почти всё, чем анализируют данные: Biopython, pandas, scikit-learn, Snakemake и даже AlphaFold.

Первые шаги состоят из четырёх вещей:
- **установить** Python и редактор (VS Code или Thonny);
- понять разницу между **REPL** (код выполняется сразу) и **файлом** (код выполняется целиком по кнопке «запустить»);
- освоить **переменные** — имена, которыми ты помечаешь данные;
- выучить **четыре типа данных**, которых хватает на 90% задач: `str` (строка), `int` (целое), `float` (дробное), `list` (список).

Первая программа — одна строка: `print("ATGC")`. Всё остальное наращивается на этот скелет.
{{< /kratko >}}

Представь, что тебе дали файл с расшифровкой генома бактерии — текстовый файл на 4,6 миллиона символов, где буквы только A, T, G и C. Нужно посчитать долю GC-пар, найти все гены, сравнить с другим штаммом. В Excel это 4,6 миллиона строк, и он умрёт на первой же формуле. Руками — несколько лет.

Именно в этот момент биологи и приходят в Python. Не потому, что программирование интересно само по себе (хотя и поэтому тоже), а потому что это единственный способ работать с данными, которых стало слишком много. Сорок лет назад один секвенатор давал тысячи пар оснований в день, сегодня — миллиарды. Биология превратилась в науку о данных, и язык этих данных — Python.

Хорошая новость: чтобы начать, не нужно учить «программирование» целиком. Через несколько разделов ты будешь считать нуклеотиды в последовательности и находить комплементарную цепь — то есть делать реальную работу, а не решать задачки про «сложи два числа».

🎯 Ты узнаешь:
- как поставить Python на Windows, macOS и Linux и проверить, что всё работает;
- чем REPL отличается от файла и почему новичку важно попробовать оба;
- что такое переменная и почему её лучше представлять ярлыком, а не коробкой;
- четыре типа данных и какой из них соответствует длине, доле, списку образцов и последовательности;
- как читать сообщения об ошибках, а не пугаться их.

## История: как физик случайно сделал язык для биологов 📜

В декабре 1989 года сотрудник голландского института CWI Гвидо ван Россум искал, чем заняться на рождественских каникулах. У института был проект на языке ABC — очень удобном для обучения, но не приспособленном к реальным задачам: он не умел работать с сетью, файлами и системными вызовами. Гвидо решил написать «ABC, который умеет всё».

Название получилось несерьёзным. Гвидо был фанатом «Летающего цирка Монти Пайтона» и назвал язык Python — «питон», хотя к змеям это отношения не имеет. Символом языка до сих пор остаётся змея, а официальная документация полна отсылок к тем скетчам.

Первая версия 0.9.0 вышла в феврале 1991 года. Дальше — три вехи, которые объясняют, почему Python победил:

- **Python 2.0, 2000 год.** Появились списковые включения и нормальная сборка мусора — язык стал удобным по-настоящему.
- **Python 3.0, 2008 год.** Разработчики решились на непопулярный шаг: сломать совместимость и убрать ошибки дизайна, которые иначе исправить было нельзя. Переход растянулся на двенадцать лет.
- **1 января 2020 года.** Поддержка Python 2 официально прекращена. Вся современная биология работает на Python 3.

Почему именно Python оказался языком биологии? Решили случай и среда. В начале 2000-х вокруг него собралось научное сообщество: появились NumPy и SciPy для вычислений, matplotlib для графиков, а чуть позже — проект **Biopython** для работы с биологическими форматами. Когда в 2010-х в биологию пришло машинное обучение, все библиотеки уже были на Python. Сейчас на нём пишут от подсчёта нуклеотидов до обучения моделей, предсказывающих структуру белка.

## Зачем биологу программировать

Есть три ситуации, с которыми биолог сталкивается регулярно, и все три решаются десятью строками.

**Файл, который не открывается.** Секвенатор отдаёт FASTA — текстовый файл, где последовательности перемешаны с заголовками. Открыть в редакторе можно, работать — нет. Несколько строк Python вытащат все последовательности в список.

**Расчёт, который нельзя сделать в Excel.** Тот самый подсчёт GC-пар в 4,6 миллиона оснований. Excel такое не загрузит, а Python считает за доли секунды.

**Повторяющаяся рутина.** У тебя 96 образцов, и к каждому нужно применить ту же формулу. Руками — вечер и три ошибки. Скриптом — один запуск, и завтра его повторит кто угодно без ошибок.

Есть и четвёртая причина, которая поначалу кажется непрактичной: **код — это документированный метод**. Когда в статье пишут «данные обработаны стандартным образом», воспроизвести результат невозможно. Когда в статье дают ссылку на скрипт — возможно. Поэтому биоинформатики всё чаще публикуют код вместе с данными, а журналы требуют его так же, как раньше требовали микрофотографии.

## Установка: что скачать, чтобы всё заработало

Есть два способа начать: полноценная установка и браузерный блокнот. Начни с того, который тебе ближе по духу, но рабочий вариант — первый.

### Способ 1: Python + редактор на своём компьютере

1. Зайди на **python.org** в раздел Downloads и скачай последнюю версию для своей системы.
2. **Windows:** на первом экране установщика обязательно поставь галочку **«Add python.exe to PATH»**. Если её не поставить, команда `python` в консоли работать не будет — это самая частая беда новичков на Windows.
3. Поставь редактор: **VS Code** (универсальный, с расширением Python) или **Thonny** (сделан специально для обучения, внутри уже всё есть).
4. Проверь установку: открой терминал (Windows: «Командная строка» или PowerShell) и набери:

```
python --version
```

Должно ответить что-то вроде `Python 3.13.1`. Если пишет «не является внутренней или внешней командой» — Python не попал в PATH, переустанови с галочкой.

> **Определение:** **PATH** — список папок, в которых система ищет программы, когда ты пишешь их имя в консоли. Если папки Python там нет, система просто не знает, где его искать.

### Способ 2: ничего не устанавливать

Если хочется только попробовать — открой **Google Colab** (colab.research.google.com). Это блокнот, который выполняется на сервере Google прямо в браузере: устанавливать нечего, нужен только аккаунт Google. Для первых шагов он не хуже настоящего Python. Для настоящей работы позже понадобится локальная установка — в Colab неудобно с большими файлами и долгими вычислениями.

### Проверка: ты увидел `>>>`

Ты в Python. Приглашение `>>>` означает, что интерпретатор запущен и ждёт команду. Именно в этом режиме мы сейчас и поработаем.

## Два режима: REPL и файл

Это первая развилка, на которой спотыкаются почти все. Python можно запускать двумя способами, и путаница между ними съедает часы.

### REPL: спросил — ответили

Запусти `python` без аргументов в терминале (или открой IDLE) — увидишь `>>>`. Набери:

```python
>>> 2 + 2
4
>>> "AT" + "GC"
'ATGC'
```

Python выполняет каждую строку сразу и печатает ответ. Такой режим называется **REPL** — Read, Eval, Print, Loop: прочитал, вычислил, напечатал, повторил. Это калькулятор и песочница: удобно проверить, как ведёт себя команда, но ничего не сохраняется. Закрыл окно — код пропал.

> **Определение:** **REPL** — режим, в котором Python выполняет каждую введённую строку немедленно и показывает результат. Обозначается приглашением `>>>`.

### Файл: программа целиком

Настоящая программа — это файл с расширением `.py`. Открой редактор, создай файл `pervyy.py`, напиши:

```python
print("ATGC")
print(len("ATGC"))
```

Сохрани и запусти (`python pervyy.py` в терминале или кнопка «Run» в VS Code). Python прочитает файл сверху вниз и выполнит все строки по очереди. Никаких `>>>` здесь нет, а чтобы что-то увидеть на экране, нужен `print()` — иначе программа честно посчитает и молча завершится.

**Правило, которое экономит время:** `>>>` печатает результат сам, файл — нет. Если в файле написать `2 + 2` без `print`, ты не увидишь ничего. Это ошибка номер один у новичков.

## Первая программа: print и переменные

### print — единственный способ увидеть, что происходит

```python
print("Привет, биология")
print("ATGC")
print(4)
```

`print()` выводит на экран то, что внутри скобок. Кавычки обозначают текст, без кавычек — число. Между элементами можно ставить запятую — они напечатаются через пробел:

```python
print("Длина:", 4)
```

```
Длина: 4
```

### Переменные: имена, а не коробки

Обычно переменную объясняют как «коробку, в которую кладут значение». Это удобно, но приводит к неверным выводам, поэтому лучше сразу привыкнуть к другому образу.

**Переменная — это ярлык (наклейка с именем) на данных.** Когда ты пишешь `dna = "ATGC"`, Python создаёт строку `"ATGC"` и приклеивает к ней ярлык `dna`. Двух коробок не создаётся: если рядом написать `seq = dna`, появится второй ярлык на тех же самых данных.

```python
dna = "ATGC"
print(dna)
```

```
ATGC
```

Знак `=` в Python — не «равно» из математики, а **присваивание**: «положи это под таким именем». Поэтому запись `4 = x` вызовет ошибку: слева должно быть имя.

Имена переменных:
- могут содержать буквы, цифры и подчёркивание;
- не могут начинаться с цифры;
- чувствительны к регистру: `Dna` и `dna` — разные переменные;
- лучше писать по-английски и понятно: `gc_content`, а не `x2`. Код читают чаще, чем пишут.

```python
dna = "ATGC"
dlina = len(dna)        # len() считает количество символов
print(dlina)
```

```
4
```

### Строка — это последовательность

Самое важное для нас свойство: строка в Python — это **последовательность символов**, у каждого есть номер (индекс). Нумерация начинается с нуля.

```python
dna = "ATGC"
print(dna[0])    # первый символ
print(dna[3])    # четвёртый
print(dna[-1])   # последний
```

```
A
C
C
```

Это значит, что последовательность ДНК в Python ведёт себя как то, чем она является биологически: упорядоченным набором нуклеотидов, к любому из которых можно обратиться по позиции. Разбираться с этим подробно будем в следующем уроке, а сейчас просто запомни: строка нумеруется с нуля.

## Четыре типа данных

В Python у каждого значения есть тип. Тип определяет, что с этим значением можно делать: строку можно сложить с другой строкой, но не умножить на число; список можно расширять, а число — нет.

Для биолога важно, что **тип повторяет тип данных в самой задаче**: последовательность — строка, длина — целое, доля — дробное, набор образцов — список.

### `str` — строка

Строка — это текст в кавычках. Одинарные и двойные работают одинаково:

```python
dna = "ATGC"
belok = 'MKTII'
```

Строки складываются — это называется конкатенацией:

```python
chain1 = "ATGC"
chain2 = "GGCC"
print(chain1 + chain2)
```

```
ATGCGGCC
```

И умножаются на число — полезно, когда нужна повторяющаяся последовательность:

```python
print("AT" * 3)
```

```
ATATAT
```

Длину строки даёт `len()`, а количество вхождений подстроки — метод `.count()`:

```python
dna = "ATGCGCGT"
print(len(dna))
print(dna.count("G"))
```

```
8
3
```

Регистр имеет значение: `dna.count("g")` даст `0`, потому что в строке нет строчных букв. Это ловушка, на которой теряют данные: последовательность в файле может быть записана как `atgc`, и половина подсчётов молча обнулится. Лечится методом `.upper()`.

> **Определение:** **метод** — функция, привязанная к значению: пишется через точку после него. `dna.upper()` означает «примени к строке dna действие upper».

### `int` — целое число

Целые числа пишутся без кавычек и без точки:

```python
count = 4
year = 1953
print(count + year)
```

```
1957
```

`int` — это длина, число копий, число прочтённых ридов, год открытия. С ним работают все обычные арифметические операции, а `//` даёт целую часть деления, что пригодится при работе с позициями на последовательности.

Крупные числа можно записывать с подчёркиваниями для читаемости — это ни на что не влияет:

```python
genome_size = 4_641_652
print(genome_size)
```

```
4641652
```

### `float` — дробное число

Дробное число — с точкой (запятая в Python означает совсем другое, запомни это сразу):

```python
gc = 0.512
concentration = 1.5e-6
```

`float` нужен для долей, концентраций, средних. И здесь важно понимать главное: **дробные числа в компьютере неточны**. Python хранит их в двоичном виде, а 0,1 в двоичной системе не выражается точно — как 1/3 не выражается точно в десятичной.

```python
print(0.1 + 0.2)
```

```
0.30000000000000004
```

Это не баг Python, а устройство двоичной арифметики с плавающей точкой — так во всех языках. Для биолога вывод практический: **доли и вероятности почти никогда не сравнивают через `==`**. Вместо `if gc == 0.5` пишут `if abs(gc - 0.5) < 1e-9`.

### `list` — список

Список — упорядоченный набор значений в квадратных скобках:

```python
samples = ["sample1", "sample2", "sample3"]
lengths = [126, 128, 130]
```

К элементам обращаются по индексу, как в строке, с нуля:

```python
print(samples[0])
print(lengths[2])
```

```
sample1
130
```

Списки можно дополнять: `.append()` добавляет в конец, а `len()` возвращает количество элементов. Именно так в реальной работе накапливают результаты обработки файлов: прочитали запись — добавили в список.

### Как узнать тип

`type()` показывает тип значения:

```python
print(type("ATGC"))
print(type(4))
print(type(0.5))
print(type(["ATGC"]))
```

```
<class 'str'>
<class 'int'>
<class 'float'>
<class 'list'>
```

И самое частое место, где это нужно: **данные из файла всегда приходят строками**. Число `42`, прочитанное из текстового файла, — это строка `"42"`, а не число. Складывать её с другими числами нельзя, пока не преобразуешь явно:

```python
raw = "42"          # это строка
number = int(raw)   # это уже целое
print(number + 1)
```

```
43
```

Преобразования, которые понадобятся: `int()`, `float()`, `str()`. Запись `"42" + 1` вызывает `TypeError` — Python не угадывает, что ты имел в виду.

## Как это выглядит на настоящей задаче

Соберём всё вместе. Задача: есть участок ДНК `ATGCGCGT`, нужно узнать его длину, число гуанинов и долю GC-пар.

```python
dna = "ATGCGCGT"
dlina = len(dna)
g = dna.count("G")
c = dna.count("C")
gc_dolya = (g + c) / dlina

print("Длина:", dlina)
print("GC-пар:", g + c)
print("Доля GC:", gc_dolya)
```

```
Длина: 8
GC-пар: 5
Доля GC: 0.625
```

Обрати внимание на три вещи, которые здесь работают и которых не было бы в Excel-формуле:

- `(g + c) / dlina` — деление всегда даёт `float`, даже если делится нацело;
- переменные называются по смыслу, поэтому через неделю код понятен без пояснений;
- поменяй строку `dna` на любую другую — всё остальное пересчитается само.

Этот приём — «доля GC» — не игрушка. GC-состав различается у разных организмов и влияет на устойчивость ДНК к нагреванию: у термофильных бактерий он выше. По GC-составу различают контаминацию в секвенировании и проверяют качество сборки генома.

## Ошибки: читать, а не пугаться

Новичок видит красный текст и закрывает терминал. На самом деле в сообщении об ошибке всегда три полезные части: **тип**, **файл и строка**, **что именно не так**. Вот четыре ошибки, которые ты встретишь в первый день.

**`SyntaxError`** — нарушен синтаксис. Обычно забыта кавычка или скобка.

```python
print("ATGC
```

```
SyntaxError: unterminated string literal
```

**`NameError`** — имя не определено. Используешь переменную, которую не создавал, или опечатался в имени.

```python
print(dnk)
```

```
NameError: name 'dnk' is not defined
```

**`IndentationError`** — нарушены отступы. В Python отступы — часть синтаксиса, а не оформление.

```python
print("A")
    print("T")
```

```
IndentationError: unexpected indent
```

**`TypeError`** — тип не подходит для операции. Классика: складываешь строку с числом.

```python
print("ATGC" + 4)
```

```
TypeError: can only concatenate str (not "int") to str
```

Последняя строка сообщения — самая важная: в ней прямо написано, что не так. Читай её снизу вверх, а не сверху вниз.

## Частые ошибки

❌ **Ждут, что файл напечатает результат сам** → в файле нужен `print()`, REPL печатает сам → иначе программа «молчит», и новичок думает, что она не работает.

❌ **Путают `=` и `==`** → `=` присваивает, `==` сравнивает → `if dna = "ATGC"` вызывает `SyntaxError`, а не сравнение.

❌ **Складывают строку с числом** → `"42" + 8` даёт `TypeError`, нужно `int("42") + 8` → данные из файлов всегда приходят строками.

❌ **Сравнивают `float` через `==`** → `0.1 + 0.2 == 0.3` это `False` → сравнивать через `abs(a - b) < 1e-9`.

❌ **Считают, что `count("g")` найдёт `G`** → регистр важен, `"ATGC".count("g")` даёт 0 → приводить к одному регистру через `.upper()` или `.lower()`.

❌ **Думают, что переменная — коробка** → это ярлык; `y = x`, а потом `x = 7` не меняет `y` → иначе неверные ожидания от присваивания.

❌ **Забывают галочку «Add to PATH» на Windows** → `python` не находится в консоли → переустановить с галочкой, это две минуты.

## Главное запомнить

✅ `print()` — единственный способ что-то увидеть на экране из файла.

✅ Переменная — ярлык на значении, а не коробка; `=` означает присваивание.

✅ Четыре типа закрывают почти всё: `str` (последовательность), `int` (длина, счёт), `float` (доля), `list` (набор образцов).

✅ Строка — последовательность с нумерацией с нуля; `dna[0]` — первый символ, `dna[-1]` — последний.

✅ `len()` — длина, `.count()` — число вхождений, `type()` — тип.

✅ Данные из файла приходят строками; числа нужно преобразовывать через `int()` и `float()`.

✅ `/` всегда даёт дробное, `//` отбрасывает дробную часть.

✅ Дробные числа неточны; для сравнения нужен допуск.

✅ Регистр важен: `G` и `g` — разные символы.

✅ Ошибку читают снизу вверх: последняя строка сообщения говорит, что не так.

## Частые вопросы

**Нужно ли знать математику, чтобы программировать на Python?**
Для начала — нет. Первые месяцы ты пишешь `len()`, `.count()`, циклы и условия: это скорее аккуратная работа с текстом, чем математика. Математика понадобится позже, когда дойдёшь до статистики и ML, — и там достаточно школьной базы.

**Python или R для биолога?**
R силён в статистике и до сих пор популярен в биологии, особенно в геномике. Python — рабочий язык ML, пайплайнов и продакшена. Оптимально знать Python и уметь читать R: на Python ты будешь строить весь конвейер, а R пригодится для отдельных статистических пакетов.

**Python 2 или Python 3?**
Только Python 3. Поддержка Python 2 прекращена 1 января 2020 года. Если в старом руководстве написано `print "ATGC"` без скобок — это Python 2, руководство устарело.

**Сколько времени до первой полезной программы?**
Первая полезная — подсчёт GC и длины — получилась в этом уроке, за один вечер. До уверенного чтения FASTA и работы с pandas обычно уходит несколько недель регулярных занятий.

**Нужна ли специальная программа?**
Нет. Достаточно Python и любого редактора: VS Code, Thonny или даже блокнот. Профессионалы чаще всего работают в VS Code или в Jupyter.

**Обязательно ли запоминать все методы строк?**
Нет. Их десятки, запоминают 5–6 самых частых, остальные ищут в документации. Умение найти метод важнее, чем помнить его.

## Лайфхаки для запоминания

- **`=` против `==`:** один знак — «положи», два — «сравни». Как один палец показывает, два пальца показывают.
- **Нумерация с нуля:** представь, что считаешь не «первый-второй», а «сколько шагов от начала». Первый символ — ноль шагов.
- **Типы по биологии:** `str` — это последовательность (ДНК), `int` — счётчик (сколько копий), `float` — доля (GC-состав), `list` — штатив с пробирками (образцы).
- **`/` и `//`:** один слэш — «дай точно», два слэша — «дай целыми».
- **Ошибку читай снизу:** последняя строка сообщения — диагноз, выше — где именно.
- **Переменная — ярлык:** `y = x` означает «ещё одна наклейка на те же данные», а не «копия данных».
- **Данные из файла — строка:** как только прочитал число из текста, сразу думай `int()`.
